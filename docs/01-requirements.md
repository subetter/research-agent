# Deep Research 工作台需求文档

项目为个人开发的 Agent 工程作品，围绕竞品与行业调研提供可持续研究的工作台。用户通过对话提出研究目标，修改计划，提供背景资料，查看证据，最终获得可编辑报告与结构化对比表。后续支持基于同一研究结果生成演示稿。

## 目标与范围

作品需要证明开发者能设计工具调用与研究循环，处理并行、上下文、长任务恢复和质量评测，并能解释技术选择及其代价。

业务成功标准是：用户能够完成一次有来源、可检查、可继续的研究。工程成功标准是：任务过程可观测、预算可控、失败可恢复，关键能力有测试和对照实验。

设计假设如下：

- 单人开发，优先桌面浏览器体验。
- 首个场景为公开信息驱动的竞品与行业调研，支持中文任务和中英文来源。
- 首版支持个人项目；数据结构保留 owner_id 与 project_id 隔离，团队协作后置。
- 通过现成模型 API、搜索 API 与嵌入服务提供推理和检索能力。
- 本阶段交付设计和实现计划，尚未建设应用。

## 用户与典型场景

主要用户是产品经理、行业研究者与需要准备调研材料的学生。用户希望减少重复检索、整理和核对来源的时间，并保留自己的背景资料与判断。

| 场景 | 用户输入 | 输出与验收 |
| --- | --- | --- |
| 竞品对比 | 比较 4 家 AI 编程工具，限定功能、定价、目标用户和信息日期 | 按维度生成对比表；重要结论关联原文；未找到的信息标注未确认 |
| 项目背景结合 | 上传自己的产品方案，再分析竞品差异 | 报告能区分用户资料与外部证据，建议明确标为分析 |
| 行业研究 | 调研某类产品的形态、商业模式和代表案例 | 分类依据明确，来源可访问，避免只罗列厂商 |
| 增量研究 | 追加一个竞品或更新某个维度 | 复用仍有效的证据，产生新版本，标出新增与变化 |
| 成果交付 | 将已确认研究结果输出为报告、CSV 和演示稿 | 输出文件与报告中的关键事实一致 |

## 完整用户流程

1. 新建项目，填写名称、研究目标和可选背景。
2. 上传 PDF、Markdown、TXT 或 CSV，查看处理状态。
3. 在对话中提交任务，限定对象、维度、时间范围、来源和输出。
4. 对关键歧义进行澄清；其余采用显式默认值，避免反复问答。
5. 展示研究计划，包含子问题、数据源、交付格式和预算。
6. 用户修改或接受计划，启动后台执行。
7. 工作台显示搜索、阅读、证据收集、补充研究与写作进度。
8. 用户可以请求暂停、取消；等待输入时提交答案后恢复。
9. 查看报告与对比表，点击结论检查支持证据。
10. 编辑成果、导出文件，或基于当前结果追加研究。

## 功能需求

P0 为最小完整研究闭环，P1 为秋招作品完整版本，P2 为后续加分扩展。

| 编号 | 优先级 | 功能 | 验收要求 |
| --- | --- | --- | --- |
| FR01 | P0 | 项目与会话 | 创建、查看、归档项目；研究历史可恢复 |
| FR02 | P0 | 结构化研究计划 | 定义对象、维度、子问题、来源范围和预算；保存计划版本 |
| FR03 | P0 | 搜索与阅读 | 搜索结果必须经过正文读取才能成为事实证据；失败有记录 |
| FR04 | P0 | 自主补充研究 | 根据未覆盖维度、冲突和缺失证据补充查询；受轮数与预算限制 |
| FR05 | P0 | 证据与引用 | 结论关联具体原文位置；来源含标题、URL、获取时间和快照 |
| FR06 | P0 | 报告与对比表 | 结构化生成；用户可编辑；CSV 与 Markdown 可导出 |
| FR07 | P0 | 进度与后台任务 | 关闭页面后任务仍可运行；重连后恢复事件；有明确终态 |
| FR08 | P0 | 调用追踪 | 可定位模型、工具、失败步骤与 Token 使用 |
| FR09 | P1 | 项目资料与 RAG | 文件异步解析；支持混合检索、重排与引用定位 |
| FR10 | P1 | 多 Agent 研究 | 按独立对象或子问题有限并行；子任务失败可局部重试 |
| FR11 | P1 | MCP 接入 | 自建资料库 Server；接入至少一个独立外部 Server |
| FR12 | P1 | Skills | 按需加载竞品、行业、报告方法；记录 Skill 版本 |
| FR13 | P1 | 任务恢复与人工介入 | 暂停、修改计划、进程故障后从检查点恢复；避免重复成果 |
| FR14 | P1 | 增量研究 | 新增对象仅研究新增范围；受影响结论和成果产生新版本 |
| FR15 | P1 | 评测面板 | 固定数据集、基线、实验结果、成本与质量可比较 |
| FR16 | P2 | 演示稿 | 从已生成结论构造结构化页面，经模板导出 PPTX |
| FR17 | P2 | 代码执行与浏览器 | 隔离分析 CSV 与生成图表；动态网页采用受控浏览器 |

## 页面设计

| 页面 | 主要内容 | 关键操作 |
| --- | --- | --- |
| 项目列表 | 名称、最近研究、任务状态 | 新建、打开、归档 |
| 研究工作台 | 左侧项目导航，中间对话与成果，右侧计划或证据面板 | 提交问题、修改计划、启动、暂停、取消、追问 |
| 资料管理 | 文件、网页来源、处理与索引状态 | 上传、启用、停用、删除、重新处理 |
| 研究记录 | 子任务、步骤、预算、异常、事件 | 查看失败、重试、恢复 |
| 成果页面 | 报告、对比表、历史版本 | 编辑、引用检查、查看变更、导出 |
| 开发者评测页面 | 轨迹、数据集、实验、评分 | 对比方案、查看低分样例 |

进度展示依据可观测步骤，例如已完成 3/5 个研究对象，不编造总体百分比。用户看到的是执行摘要、工具动作和证据，不展示模型内部思维链。

## 非功能需求与验收目标

以下为实验条件下的目标，外部模型和搜索延迟单独记录。

| 维度 | 目标与条件 |
| --- | --- |
| 普通 API | 本地或固定测试环境中，不含模型推理的 CRUD 请求 p95 小于 500 毫秒 |
| 任务提交 | 固定环境中 p95 小于 2 秒返回 run_id；实际研究在后台运行 |
| 并发 | 默认单任务至多 3 个 Researcher；先验证同时运行 2 个研究任务 |
| 重连 | 断开 SSE 后按事件序号恢复，无不可解释的进度缺失 |
| 故障恢复 | Worker 被结束后恢复到最近有效检查点；最终业务成果不重复创建 |
| 隔离 | 所有项目资源和下载接口验证 owner_id 与 project_id |
| 成本 | 记录模型与工具费用；运行预算超限后停止新增调用并交付部分结果 |
| 可复现 | 固定来源快照、模型标识、Prompt、Skill、配置与代码版本 |

## 首版边界

首版支持公开网页与用户上传资料，不包含付费数据库采购、团队实时协同、移动端、自主外部写操作和通用电脑操作。用户手动编辑的文字保留编辑记录；不能自动宣称仍通过系统引用验证。

报告中的确定事实、推断建议和未确认项使用不同标记。多个网页转述同一公告不能视为多个独立证据。证据冲突保留原始口径、日期和适用范围，不强行合并为一个答案。

## 待实施时确认的参数

开发时间、预算上限、模型与搜索服务可用性、部署环境尚未由用户指定。实现时使用配置项承载，先完成本地 Docker Compose 演示，再决定公网部署与服务采购。
