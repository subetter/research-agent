# 研究预算与失败恢复

更新日期：2026-10-08。

## 当前策略

- `MAX_MODEL_CALLS=80`：每条研究累计模型调用次数，包括规划、调查、补充和报告。
- `REPORT_RESERVED_CALLS=4`：研究阶段最多使用 76 次，报告可使用总额度内的剩余次数；预留不增加总额度。
- `MAX_SEARCH_CALLS=24`：新计划的搜索上限；已确认的旧计划保持原上限。
- 搜索按对象分配，每个对象最多使用 `max(1, floor(计划搜索上限 / 对象数))` 次，跨补充轮次累计。不能均分的余量保留，总上限始终生效。
- 已确认未知或仍在执行的调用仍计入预算；不会因重试清空账本。已成功的调用复用缓存。
- 研究模型额度耗尽时退出工具循环，保留已取得的证据；预算不足时不启动补充调查，进入报告阶段。缺口检查按对象×维度格子，补充轮只针对未覆盖格子做定向检索，不把整个对象重搜一遍。
- 报告输出缺失事实为待确认项，引用校验仍仅保证结构与证据 ID 合法。

## 页面

显示模型、搜索用量与上限、保存的证据条数，以及报告预留额度。预算为调用次数限制，不等于 API 账户余额；用量包括成功、未知和执行中的预留调用。报告阶段显示“正在综合证据与生成报告”。失败页面显示原因和恢复说明。

## 重试

从 LangGraph 的失败步骤恢复，保留证据、成功调用缓存和账本。原 40 次模型预算耗尽的报告任务，在新 80 次限制下可继续；旧计划搜索上限不会自动上调。未知调用不自动再次收费，可能需要人工确认后进一步恢复；重复点击不会重置预算。达到新的总上限后不能靠重试无限调用。

提高次数上限可能增加实际 API 费用。尚未实现按金额或 token 的硬预算。

## 应用更新

双击项目根目录 `重启工作台.command`，或运行 `bash scripts/restart.sh`。脚本仅停止工作目录位于当前项目内、监听 3000/8000 的进程；其他应用占用端口时会拒绝停止。终端需保持打开。
